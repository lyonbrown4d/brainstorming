# macOS 窗口按钮位置：临时处理与上游问题草稿

2026-11-01。用户已批准本轮在应用侧加入可移除的临时恢复处理，以继续完整 macOS 验收。本文记录移除条件和可提交上游的问题说明；尚未向外部仓库发布 issue。

## 已复现的问题

- 环境：macOS 27.2、Apple M1 Pro、arm64、DPR 2。
- 依赖：Tauri 3.0.0-alpha.5、tauri-runtime-cef 3.0.0-alpha.6、CEF 154.0.8037.98。
- 运行时有效配置：`decorations: true`、`titleBarStyle: Overlay`、`hiddenTitle: true`、`trafficLightPosition: { x: 20, y: 22 }`。
- 启动恢复和外观切换后，窗口按钮与 44 点标题栏对齐；通过 Tauri 将真实窗口调整为 1280×800 后，三个按钮恢复系统默认位置，中心 y=16，标题栏中心 y=22。
- 分段复验确认双向缩放恢复后位置正常，但创建文档更新原生标题后再次偏移，期间没有新的 resize 事件。CEF 的 `SetTitle` 路径没有执行位置恢复。
- `tests/native/00-startup.spec.ts` 保留 2 点偏差上限，在缩放后失败。不是 DOM 模拟尺寸，也没有放宽断言。

## 临时处理范围

应用在 macOS 编辑工作区就绪后，收到新尺寸或实际标题变化时，合并同一窗口的恢复请求，短暂延后一次，通过 Tauri 官方 `set_traffic_light_position` 恢复原有配置。相同尺寸事件去重；标题确有变化时允许恢复同一尺寸，同窗口最多一个待执行任务；跳过全屏、销毁时清理。不直接改写 AppKit 帧，不轮询或自动重试。

这是用户批准的临时适配，不能替代上游修复。采用已修复的上游版本后，删除本地恢复模块及其注册、启动和事件接线，重新验证启动、浅深色切换、双向缩放、文档标题与脏状态变化、全屏退出和多窗口。删除临时处理后同一组回归通过，才算满足移除条件。

## 上游问题草稿

目标仓库：[tauri-apps/tauri](https://github.com/tauri-apps/tauri)。相关发布源码为 `crates/tauri-runtime-cef/src/platform/macos/window.rs`；发布提交 `1991873f5e2baa68773f21465f61baa93077498f`。正式提交前仍需检查重复 issue、仓库模板、现有标签和可用指派人。

**标题：** macOS CEF overlay window loses configured traffic light position after resize or title changes

**最小复现：**

1. 使用上述版本创建带 Overlay 标题栏的窗口，配置按钮逻辑位置 `{ x: 20, y: 22 }`。
2. 显示并聚焦窗口，通过官方位置接口恢复坐标，确认位置生效。
3. 通过 `Window::set_size` 调整实际窗口尺寸，例如 1440×900 → 1280×800 → 1440×900。
4. 等按钮恢复后更新原生窗口标题，再检查位置。
5. 在 AppKit 主线程只读测量标准窗口按钮的位置。

**预期：** 启动、外观切换和窗口尺寸变化后，配置的按钮位置保持有效。

**实际：** 尺寸变化后按钮回到默认中心 y=16，与应用标题栏中心相差6点。运行时配置仍为 `{ x: 20, y: 22 }`。

**源码证据与待确认部分：** 发布 crate 的校验值与锁文件一致；配置读取、官方 setter 和 AppKit 窗口句柄路径均已核对。resize observer 当前同步恢复，而 appearance 路径通过下一轮 run loop 恢复。观察结果与布局结束后再次重置的时序相符，但尚未用上游最小工程确认具体回调顺序；该推断应与实测结果分开表述。

**上游验收：** 在无应用侧补偿的最小工程中，启动、外观切换、连续和双向缩放、标题变化、全屏退出后均保留配置位置，不产生恢复循环或无界待执行任务。下游采用修复版本并移除补偿后，真实 CEF 窗口回归通过。
