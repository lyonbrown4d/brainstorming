# `.brainstorming` 单文件协议

原生文件为 SQLite 数据库，密码保护文件使用 SQLCipher。原生协议版本为 **2**，`application_id` 为 **`0x42524E54`**。不兼容此前的原生协议、ZIP / JSON 文件、本机数据库或恢复记录；文件后缀保持 `.brainstorming`。

## 文档与表

一份文件对应一份多 Sheet 工作簿。每个 Sheet 保留独立的主题树、结构、样式、资源引用和演示内容；资源二进制可以共享。TypeScript 编辑器的工作簿 JSON 版本为 2、单页模型版本为 1，与 SQLite 文件协议分别演进。

| 表                       | 内容                                           |
| ------------------------ | ---------------------------------------------- |
| `document`               | 工作簿 ID、名称、协议及必需功能                |
| `sheets`                 | 画布 ID、顺序、名称、根节点和画布设置          |
| `topics`                 | 主题、父级、有序位置、标题和可选元数据         |
| `annotations`            | 关联线、外框、概要、标注、笔迹和演示等有序结构 |
| `group_members`          | 外框 / 概要的有序主题成员                      |
| `resources`              | 各画布的资源身份、名称、类型及对象引用         |
| `topic_resources`        | 主题的图片、音频、附件等有序引用               |
| `resource_objects`       | SHA-256 寻址的不可变对象及长度                 |
| `resource_chunks`        | 对象的 256 KiB 分块和逐块摘要                  |
| `resource_variants`      | 原始对象的预览派生物                           |
| `image_tiles`            | 各分辨率与坐标的瓦片对象                       |
| `document_revisions`     | 最近 20 次写入的结构快照                       |
| `revision_resources`     | 历史版本引用的不可变资源对象                   |
| `document_preview_state` | 成功保存快照的摘要与封面 Sheet                 |
| `document_previews`      | 各 Sheet 的有界 PNG 系统预览                   |

表结构由 SQLx Migrator 管理，显式 SQL 位于 `src-tauri/src/document/migrations`，通过 `migrate!` 编译进应用。履历表固定为 `_brainstorming_migrations`，保存版本、校验和与执行状态；初始迁移编号为 1，与 `user_version=2` 的文件协议标识分开。只执行应用内迁移，不执行文件携带的脚本；已发布迁移不修改，新变更追加文件。应用标识、协议、必需功能、迁移履历或校验和无效时拒绝打开。

此前由当前 Tauri 协议生成、尚无迁移履历的文件，必须通过初始表结构和工作簿数据校验，才能在事务内由 SQLx 登记为基线；不重建或丢弃正文。此登记不适用于旧 Electron/Kysely 格式。

主题维持稳定 ID、唯一父级和有序子主题。Swift / Kotlin、React Flow 与 Lexical 的运行时对象不进入文件。活动画布、选区、文本草稿、视口、面板状态和撤销栈只留在会话。

## 图片、视频与附件

原始媒体嵌入同一 SQLite 文件，不依赖源文件的磁盘路径。二进制按 SHA-256 去重，多 Sheet、复制画布和历史快照可共享同一对象。资源 ID 在各 Sheet 内独立，不会因不同画布使用同名附件而覆盖。

原始资源导入和导出按块处理。图片通过 libvips 生成 WebP 预览与 512 像素 DeepZoom 瓦片，重采样不改变原始字节。不同平台的 codec 由固定版本原生分发决定，无法解码时明确报告，不能用占位图冒充成功。具体支持范围见 [原生图片库](native-libraries.md)。

视频和附件使用有界 Range 流式读取；资源服务的普通 GET 同样按块响应，不会为方便而先拼成一个完整缓冲区。资源 URL 具有会话令牌，只允许对应应用来源访问，不能作为任意文件读取接口。

编辑器边界传资源描述和对象引用，不把大文件转成 base64 保存在 Zustand。有限的 XMind、剪贴板和浏览器 File 输入仍有独立的内联大小上限。保存时重新校验元数据、引用、对象长度和摘要。

## 保存、密码与连接

已有文件通过 SQLite 事务保存；首次保存失败不会发布半成品。另存为复制结构、所有仍被引用的资源、派生物和文件内历史。密码更改通过临时 SQLCipher 文件和原子替换完成，失败保留旧文件和旧密码。

正文、资源和版本记录使用同一文件密码。恢复副本维持密码保护；密码不写入最近文件、本机索引或日志。解锁令牌有有效期，前端激活成功后才建立文档会话。关闭标签和应用退出释放凭据与连接租约。

数据访问统一使用 SQLx 异步 API；SQLite 的同步调用由 SQLx 的后台工作线程执行。相同规范路径和凭据复用 `SqlitePool`，不同文件独立建池；文档保存、历史、资源块和改密共享路径级操作门闩。资源复制使用独立只读连接固定源快照，避免跨文档复制相互等待。关闭等待已经开始的借用，拒绝关闭后排队的新借用。

## 文件内系统预览

`002_document_previews.sql` 追加预览表，不修改迁移 001，也不改变文件协议版本。`document_preview_state.input_hash` 识别成功保存的输入快照，`content_hash` 对应资源规范化后的工作簿；PNG 的 `source_hash` 必须与当前 `content_hash` 一致。正文保存事务同时移除摘要已过期的 PNG，后台生成完成后再次比较摘要，过期结果不写入。

预览格式版本为 1，每个 Sheet 最多保存一张 PNG；单边不超过 1600 px、每张不超过 1 MiB、整份文档不超过 16 MiB，最多 128 个 Sheet。封面使用最后一次保存时的活动 Sheet。预览与正文位于同一数据库，改密时随整库复制和加密。

前端在手动保存或自动保存成功后生成预览；未命名文档不进入队列。队列合并同一文档的连续保存，一次只渲染一份文档；较新的保存和关闭会取消旧任务。预览失败不撤销成功保存，也不触发正文保存重试。IPC 通过现有会话确定文件，只接受该文档的成功保存快照，不接收任意文件路径。

系统提供程序只读嵌入 PNG 和有限的 Sheet 元数据，不启动 React、不访问网络、不解密、不迁移文件。加密文件不生成或提供系统预览；已有预览随数据库加密。旧文件、缺失或过期的预览、损坏数据和不支持的预览版本不返回图像，由系统使用通用图标。各平台实现与验收状态见 [开发说明](development.md#系统文件预览的平台状态)。

## 本机数据与移动文件

语言、最近文件和恢复索引位于独立本机元数据库 `brainstorming-native-v2.sqlite`。恢复正文保存在 `recovery-sqlite-v2` 目录，每次先完成一代正文，再替换索引。新版本不读取旧元数据文件。

iOS / Android 系统文件可能是安全范围 URL 或内容提供者 URI。平台插件管理授权和工作副本；保存成功以真实原生写入或系统导出完成为准。iOS 首次导出先生成完整文件，再交给系统选择器；取消不改变文档的成功保存状态。

## XMind 与交换格式

XMind 不是本机存储格式。导入器识别 ZIP 内现代 `content.json` 与旧版 `content.xml`，经校验转换为工作簿并返回报告。导入文档没有正式保存路径，首次保存生成 `.brainstorming`，不能覆盖源 `.xmind`。

支持现代 XMind 导出，以及 Markdown、OPML、纯文本大纲和 PNG / JPEG / WebP / SVG / PDF 图形导出。第三方格式的完整语义和视觉不能保证无损，导入报告列出不支持内容；Brainstorming 扩展字段用于自身导出后再导入。ZIP 解压、XML 和 Markdown 解析复用维护中的第三方库。

导出对话框从完整布局生成含嵌入资源的 SVG，再通过原生 `resvg` / `image` 渲染和编码 PNG、JPEG 与无损 WebP；JPEG 默认质量为 92，透明区域填白。SVG 保留矢量内容，字体依赖查看设备。位图默认以 2× 输出，并自动适配单边 16384 px、总计 4000 万像素的限制。PDF 仍将栅格图适配到单页 A3，文字不可搜索。

## 主题表现、笔迹与演示页面

主题形态存于 `style.shape`，与主题层级和资源引用分开；支持的 16 个值以 `src/core/types.ts` 的 `TOPIC_SHAPES` 白名单为准。切换形态不移除原有内容。画布节点和导出轮廓由这些持久化值投影，React Flow 对象不写入文件。

主题手动宽度存于 `style.width`，为 80–1200 之间的有限数，单位为缩放前的画布像素；字段缺省表示适应内容。布局与导出根据宽度换行，圆形会保持等宽高并在内容过高时增大。宽度进入既有主题样式 JSON，无需新增数据库列或修改已发布迁移。

主题整体比例存于可选 `style.scale`，为 0.5–3 之间的有限数，缺省为 1。文字、图标、图片与形态按此比例统一缩放，原有字号、图标大小与手动宽度不改写；布局尺寸和连线边界采用缩放后的值。该字段复用主题样式 JSON，随 SQLite、版本化 JSON、分支剪贴板和 Brainstorming 的 XMind 扩展保存，不增加数据库迁移或文件协议版本。第三方 XMind 不保证呈现此扩展比例。

主题的可选 `style.spatialDepth` 保存 3D 深度增量，必须为 −1,000,000–1,000,000 内的有限数，缺省为 0。当前主题及其后代继承该增量；游离主题从独立根开始。该字段不改变 2D 布局、节点尺寸或测量结果。它复用主题样式 JSON，随 SQLite、版本化 JSON、分支剪贴板和 Brainstorming 的 XMind 扩展保存。

Sheet 的可选 `settings.spatial` 保存空间视图配置。存在时必须同时包含 `mode`、`yaw`、`pitch`、`spacing`：`mode` 为 `2d` 或 `3d`；`yaw` 为 −π–π、`pitch` 为 −π/2–π/2、`spacing` 为 0–200，三个数值均须有限。可选 `target` 须同时包含 `x`、`y`、`z`，各分量为 −1,000,000–1,000,000 内的有限数；缺省为原点。画布坐标的 `x` 向右、`y` 向下、`z` 朝向观察者。缺省按 2D 视图打开。视图模式、视角、相机目标和层距通过 `setDocumentSettings` 进入文档历史；拖动中的预览不写入文件。透视镜头距离仅属于渲染会话，不写入该对象。该对象复用 Sheet 设置 JSON，随 SQLite、版本化 JSON 和 Brainstorming 的 XMind 扩展保存，不增加 SQL 迁移，也不修改 JSON 或文件协议版本。第三方 XMind 不保证呈现这些扩展值。

概要分组可包含 `summaryTopicId`，引用与源范围同级的真实主题，主题及后代仍使用普通主题树。源范围由有序 `topicIds` 表示；显式创建和调整范围时检查连续、同父、同侧。文件校验拒绝中心主题、重复关联和祖先自包含引用；结构移动可能解除不再安全的关联，原主题内容保留。删除源范围、概要或概要主题时清理关联，复制粘贴重映射 ID；旧的纯文字概要仍可显示。字段复用有序注解 JSON，不添加独立的概要子主题表。

主题的 `metadata.task.priority` 保存 1–9 的整数优先级，同一主题只保留一个等级。`done` 为可选布尔值；仅有优先级不代表未完成任务，不自动补入完成状态或进度。清除最后一个任务字段时移除空 `task`。XMind 导入和导出使用标准 `priority-1` 至 `priority-9` 标记。

关联线保存在 `annotations` 的 `relations` 类别中。`routing` 支持 `straight`、`curve`、`orthogonal`；可选的 `sourceAnchor` / `targetAnchor` 保存端点方向，`controlPoints` 保存两个曲线控制点，`waypoints` 保存 1–32 个折线路径点，`labelOffset` 保存标签偏移。几何坐标必须为 ±1,000,000 内有限数。画布、图形导出与原生读写使用同一组持久化字段，不保存拖动中的临时位置。

每个 Sheet 的 `drawings` 存入 `annotations` 的 `drawings` 类别；每笔保存 ID、颜色、粗细和坐标 / 压力点。可选 `spatialDepth` 保存笔迹的空间深度，范围为 −1,000,000–1,000,000，缺省为 0。可选 `transform` 保存平移 `x/y` 与正数缩放 `scaleX/scaleY`，保留原始采样和压力；缩放限制为 0.001–1000，平移为 ±10^10，变换后每个采样点仍须落在 ±1,000,000 内。读取与写入均校验最多 2,000 笔、每笔 8,192 点和合计 262,144 点，坐标为 ±1,000,000 内有限数，压力为 0–1，宽度为 1–24。游离想法仍使用主题树及 `floatingPositions`，不转成笔迹。主题的 `style.offsetX/offsetY` 保存自动布局后的子树平移量，单轴限制 ±1,000,000；游离根不继承中心主题偏移。笔迹变换复用有序注解 JSON，主题偏移复用现有样式 JSON，不修改已发布迁移。

演示的 `presentation` 有序数组保存主题 ID 与可选的 `layout`、`hidden`、`notes`、`reveal`、`appearance`；未保存编排时临时生成页面。`appearance` 保存演示页独立样式：`background` 为六位十六进制背景色；`title` / `body` 支持 `scale`（0.75–1.5）、六位十六进制 `color`、布尔 `bold` 和 `align`（`left` / `center` / `right`）；`image` 支持 `fit`（`contain` / `cover`）及 `position`（`left` / `right`）。字号按版式基准同比调整，仍由版式自动排布；不写入画布主题样式。以上字段经 Rust 校验后复用 `annotations` 中的演示 JSON 保存，不新增表或修改已发布迁移。播放页索引、逐项进度、计时、全屏和演讲者状态只留会话。旧 `presentation.camera` 字段可被读取，但不控制 3D 导图视角；导图视角由 `settings.spatial` 保存。
